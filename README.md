# Лабораторная работа № 6 — ООП на Python

Решения всех заданий из 19 предоставленных ноутбуков. В каждом ноутбуке сохранено исходное условие и заполнена ячейка решения. Для запуска вне Jupyter те же классы вынесены в файлы Python. Каждый файл задачи самодостаточен: одноименные классы из разных задач не мешают друг другу.

## Запуск

Требуется Python 3.10 или новее. Внешние зависимости для исходников, примеров и тестов не нужны. Откройте `lab06.code-workspace` в VS Code или терминал в этой папке.

```bash
python run_all.py
python -m unittest -v
```

Первая команда показывает работу классов, вторая проверяет основные сценарии, граничные случаи и ошибки. Ноутбуки `.ipynb` можно открыть в Jupyter или VS Code с поддержкой ноутбуков. В самих ноутбуках содержатся определения классов; примеры находятся в `run_all.py`.

## Особенности условий

- В Python нет встроенного `ArgumentError`. В задании 01 он определен как наследник `TypeError`. `get_distance` принимает названия метрик на русском и английском: `евклидово` / `euclidean`, `Чебышева` / `chebyshev`, `городских кварталов` / `manhattan`.
- `bool` не принимается вместо целого числа в заданиях, требующих именно целые числа.
- В условии `Boat` одновременно упомянут входной `kind` и обязательное значение `Boat`. Поддерживаются вызовы `Boat("Яхта", 40, "Иван")`, `Boat("Яхта", 40, "Boat", "Иван")` и именованный `owners_name`; сохраненный `kind` всегда равен `Boat`.
- Для неподдерживаемых сравнений шахматистов и сладкоежек возвращаются именно строки из условий, а не исключения.
- Операции с векторами и кошельками создают новые объекты. Исходные объекты не изменяются.

## Проверки

`test_lab06.py` содержит отдельную проверку каждого из 18 номеров задач и проверку загрузки всех 19 ноутбуков. Проверяются точные сообщения, ошибки типов и значений, сохранение исходных объектов, пустые стеки и векторы, свойства и наследование.
